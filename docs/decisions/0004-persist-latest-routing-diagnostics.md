# ADR 0004：持久化最近一次路由决策诊断

- 状态：accepted
- 日期：2026-09-16

## 背景

阶段 C/D 已经生成结构化 `FailureDecision`，并在运行时日志中记录动作和风险。但仅有日志不便于 `/switch status` 和跨会话排查；同时将每次完整 attempt 历史写入配置目录会增加文件体积和敏感信息暴露面。

## 决策

1. `StatsManager` 在每条 binding/账号线路上保留最近一次 attempt 的诊断摘要：HTTP 状态、`Retry-After`、请求阶段、错误类别、失败作用域、动作、成本风险、稳定原因码、用户可读原因、冷却、熔断决定和尝试预算。
2. `/switch status` 同时展示成本/缓存统计和该线路的最近诊断；完整 attempt 仍通过日志和测试验证，不新增独立诊断文件。
3. 成功 attempt 没有 FailureDecision 时清除该线路旧的决策字段，避免状态页显示过期原因。
4. 诊断不包含 API Key、认证 Header 或原始 Session ID；缓存 Usage 仍只用于观测，不参与历史自适应选路。

## 后果

- 常见故障可在请求结束后通过状态命令解释，且旧 `stats.json` 可由既有归一化逻辑继续读取。
- 诊断是“最近一次摘要”而非完整审计日志；需要完整时间序列时应使用外部日志或后续专门的事件存储设计。
- `cacheDomain`、账号配额策略和更细的 timeout 阶段仍不在本决策范围内。
